# v0.4.0

## Outcome

This release reduces routine draft traffic, improves same-browser recovery, and
removes hashed frontend assets as a deployment failure mode.

## Changes

- Drafts are buffered immediately in user-, run-, decision-, and
  revision-scoped browser storage.
- Cloud autosave is debounced for ten seconds.
- Review, evidence ordering, Run Centre navigation, and sign-out carry the
  latest draft immediately.
- A normal Supabase draft save is one conditional request.
- A cold cloud resume loads the canonical run and draft in one request.
- The active run and draft are reused inside the current Streamlit session.
- Frontend build outputs are stable `index.js` and `index.css`.
- The loader prefers stable assets and tolerates one legacy hashed bundle.
- The canary campaign contract is documented.

## Compatibility

- Existing encrypted cloud runs remain readable.
- Existing draft rows remain readable.
- No Supabase migration or secret change is required.
- Local Alpha runs and completed-run exports remain compatible.
